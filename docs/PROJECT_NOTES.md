# MTF 项目结论

整理日期：2026-09-14。本文合并旧状态、路线图、复盘和研究资料，只保留
结论；过程、逐条候选分级与旧方案可在 Git history 中查看。历史结果不是
本轮验证结果，待办不是执行授权。

## 当前决策

- 项目包含通用代码文档生成工具和具体竞赛模板库，开发期保持高度耦合；
  当前不讨论通用工具的进一步设计，也不推进拆分。
- 模板库只收稳定 Template、高频 Snippet 和最小 Usage，不建设知识库、
  题解库或 Template / Trick / Problem 关系系统。内容规则以
  [CONTENT_GUIDE.md](CONTENT_GUIDE.md) 为准。
- 执行权限统一见 [AGENTS.md](../AGENTS.md)：管理文档整理不能扩展成正文
  改造；HTML 按产出变化渲染，PDF 按明确要求渲染；模板正确性测试按明确
  要求执行，语法与编译检查可按需执行。

## 已有实现与可靠性结论

- 工具链已从 Rust 迁移为 Python `mtf` 包；现有入口为 `render` 和
  `verify`，不恢复旧头文件树或 sync/bundle/workspace 子系统。
- 渲染器支持离线单文件 HTML 与四份 PDF（竖排双栏/横排三栏，各有彩色/
  黑白版本）。完整渲染使用暂存产物后替换；仅 HTML 的操作见 README。
- 算法实现从 Typst 正文导出，driver 不保留第二份实现；catalog 记录
  映射与覆盖，不等于当前实现通过判题。
- 验证器编译可并行，正式用例串行计时；记录最慢用例，超过时限 60% 提醒，
  首次 TLE 串行复核并保留痕迹。历史优化耗时不能替代当前性能结果。
- manifest 只表示最后一次运行范围，子集运行也会重写；失败现场目录每轮
  清理，不能作为永久档案。具体命令和副作用见 README。
- 已有结构、HTML/PDF 质量、独立与合并语法检查，以及 CI 和定期官方判题
  配置。已有自动化配置不构成 Agent 自行启动正确性测试的授权。

## 历史验证基线与缺口

以下摘自截至 2026-09-05 的旧报告，未在本次整理中重新运行，也未绑定当前
源码提交；不能据此声称当前版本全绿。

- 2026-08-10：当时 17 项官方检查中 16 项通过，Dinic 在
  `augmented_cycle_00` 初测与复核均超过 5 秒。更早的通过或优化结果不
  消除这次失败，性能风险尚需重新验证。
- 2026-08-30：当时 47 个模板独立及全书合并语法编译通过，18 项 driver
  接口编译通过；NTT 官方 `convolution_mod` 53/53，FFT/NTT 随机对拍
  2000 组通过。后两者是历史正确性结果，不能推广到后续修改。
- 截至 2026-09-05，旧报告记录 catalog 有 55 个模板、18 项官方检查覆盖
  19 个模板。这是登记覆盖数量，不是 19 个当前实现通过的证明。
- 旧报告明确未复验的变更包括动态开点线段树、线性递推、更新的字符串
  模板、MST、虚树与 DSU on Tree；0-1 BFS 未接专用官方检查。
  Z 函数的官方通过结果来自更新前实现，不能沿用为新实现证明。
- KMP、浮点 FFT、组合数等缺少直接匹配的官方验证契约。不要为取得徽章
  把 driver 改造成另一个算法；浮点 FFT 的对拍不等于官方数据验证。
- 旧记录提到 Typst 实验性 HTML 导出和 Poppler tagged PDF 的 `Suspects`
  提醒。升级工具或处理打印质量时需重新判断，不当作永久故障或已消除问题。

以后记录验证结果时注明日期、源码提交、检查范围和未验证部分；只登记映射
或通过语法检查时，不使用“已验证正确”的措辞。

## 结构改造的保留教训（2026-08-09）

- 物理文件组织不等于标题层级。一级标题由 `book.typ` 持有，不能在每个
  正文文件重复；合并应形成连贯主题，而不是把局部小节直接拼接。
- 不在需求未授权时扩大内容模型、批量迁移或添加渲染组件。结构决策有歧义
  时澄清具体变化，不把历史“十行方案、样板、逐轮确认”变成所有任务的
  固定审批流程。
- 使用示例只说明接口，不搬入题目专属输出校验协议；避免自动扩写长说明、
  元数据卡片和关系文字。打印与网页交付按实际授权分别处理。

## 研究结论（历史候选，非收录计划）

### AlgoWiki 与 VUQA（2026-08-04 至 2026-08-05）

- AlgoWiki 的 172 条目录曾按 S/A/B/C/D 分级，VUQA 合并后为 173 条。
  当时的“优先入库”依赖旧 Trick 方向，现已不作为收录指令；只有形成当前
  模板库允许的稳定实现或高频片段时才重新评估。
- 动态区间 MEX 可转成每个值相邻出现位置间隙对应的二维带权查询；候选
  尚缺动态二维最小值结构、删除/重数语义和边界验证，不是成品模板。
- VUQA 约数个数表的 18 行在旧研究中完成数值核验；见证只保证是一个
  最大值取得点，不保证最小见证。数值参考表不因此成为独立 Trick。
- 静态区间 LIS/Monge 资料仅是研究方向；复杂性图混合上界、归约和条件
  下界，“NP-Hard”标题也不能替代计数问题的精确分类，不能直接移入正文。
- 来源未明确许可证时不复制整份源码、外站正文或整图。保留的 JSON 是
  目录元数据、结构化转述与来源线索，不参与 `book.typ` 或 catalog。
  固定来源为 VUQA 提交 `c74b9a525cfe1c16cd851a9d0d43c442e10b37ef`；
  原始链接和逐项判断可查 `docs/research/` JSON 与 Git history。

### nk 筛选（2026-08-10）

- 已吸收：`6/Full Alphabet.cpp` 的 Z/exKMP、`2/Hyperspace Pairing.cpp`
  的 Gray Code；此前吸收矩阵快速幂（`3/Not Aqre 2.cpp`）、Kruskal 重构树
  （`1/P1967 [NOIP 2013 提高组] 货车运输.cpp`）、线性基（`2/b.cpp`）。
- `3/Uphill Duel.cpp` 的博弈图逆推尚需明确环上平局与接口；
  `1/Fish Eating.cpp` 和 `3/Bitmask.cpp` 依赖题目语义；
  `5/Sequence（Mex Version）.cpp` 有双哈希碰撞和接口不稳定问题，暂不吸收。
- `5/Koishi and Function.cpp` 的最小质因子状态不并入现有 primitive
  线性筛；前驱掩码拓扑序计数属于状压 DP，不按模板搬运。其余题解、构造、
  暴力核验及未完成代码不直接吸收。几何代码当时未纳入筛选。

## 待讨论方向

以下保留自旧路线图，不承诺优先级或排期；执行前由用户确定范围。

- 验证：Dinic 性能回归、历史结果对应新实现的复验、无对应官方题的本地
  对拍机制、每次最慢用例耗时历史。运行正确性测试仍需明确要求。
- 模板：运行时模数组合数变体、离线算法（预留 `80_offline`）、几何
  （预留 `90_geometry`，核对 `nk/1/Geometry Textbook.cpp` 的 cp-template
  来源与许可）、可形成稳定实现的反悔贪心。预留分类不要求现在创建目录。
- 内容质量：按需要补充接口约定与复杂度检查，不机械扩充正文。
- 发布可追溯性：产物记录源码版本与构建日期。
