# MTF 内容规范

MTF 只维护竞赛模板手册，不在本仓库建设算法知识库或题解库。正文的目标是：
比赛时能快速判断接口约束、复制代码并完成修改。

## 收录范围

`src/` 只收三类内容：

1. **Template**：有稳定接口、可复用且能够独立验证或编译的实现；
2. **Snippet**：没有必要封装成组件，但赛时会反复手写的短代码；
3. **Usage**：说明模板如何调用、定制或组合的最小示例。

概念推导、算法比较、识别方法、专题知识笔记和完整题解不进入正文。尚未形成
模板的候选资料可以保存在 `docs/research/`，但它们不参与渲染，也不代表收录
计划。

动态规划的状态设计、转移、优化和题型代码属于知识库，不进入本模板库；即使
某道题的 DP 能封装成函数，也不以“专用模板”的名义收录。背包、区间 DP、
树形 DP、数位 DP、状压 DP 等统一遵守这一边界。

现有 SOS 条目表达的是子集 zeta/Möbius 变换，不作为收录其他 DP 代码的先例。
包含题目输入输出、特殊构造或答案协议的实现同样属于题解，不进入正文。

## 模板条目

一个模板条目按需包含以下内容：

1. 一句话用途；
2. 下标、区间、返回值和副作用等接口约定；
3. 正确使用所必需的前提或不变量；
4. 时间、空间复杂度；
5. 唯一一份完整实现；
6. 必要时附最小调用或泛型实例。

正文不抄题面，不保留题目特有的输入输出或答案校验协议。例题编号只可用于
说明模板对应的验证来源，不能把题解伪装成模板用法。

## 排版语义

- 复杂度、等式、不等式、集合关系、下标范围和区间等数学表达使用
  Typst 数学模式 `$...$`；需要独占一行时，在两个 `$` 内侧留空格；
- HTML 中普通成对定界符固定为正文数学字号，以保持 LaTeX/KaTeX 的
  `(...)` 观感；确实需要随分式、矩阵等内容伸缩时显式使用 `lr(...)`；
- C++ 类型、标识符、函数调用、字面量和可直接复制的代码表达式使用
  反引号代码样式；不用代码样式代替数学公式。

## 代码真源

完整实现以 `src/**/*.typ` 中交给 `snippet` 的代码为唯一真源。
`mtf verify` 从同一段代码导出提交，不在 Markdown、driver 或其他章节复制
实现。验证状态只由 `verify/catalog.json` 和验证结果维护。

## 章节与文件

- `book.typ` 唯一负责一级标题和全书顺序；
- `src/**/*.typ` 从二级标题开始，不得重复一级标题；
- 二级标题表示算法或主题，共享同一主题的多个实现、变体或紧密子接口
  使用三级标题；HTML 侧栏与 PDF 目录均展示到三级；
- 正文不跳级使用标题，不再使用四级及更深标题，更细的内容改用列表
  或段首强调；
- 文件夹和文件名只负责物理组织，不自动生成书籍标题；
- 一级分类目录使用十的倍数编号；正文文件使用全仓库不重复的两位序号，
  在章内递增，不得与其他章节复用；
- 一个文件可以容纳同一主题下紧密相关的多个模板，但合并前必须先写出完整
  标题树；
- 新文件必须显式加入 `book.typ`，且每个正文文件只能被包含一次。

## 修改与检查

按改动范围执行最小且充分的检查：

- 文字、标题或目录调整：运行内容结构测试并渲染 HTML；
- 模板代码调整：再运行 `mtf verify --syntax-only` 或对应的定向检查；
- 打印样式调整：生成并检查四种 PDF；
- 批量整理：先完成一个二级章节样板，确认后再扩展。

未经明确要求不新增内容类型、关系模型、渲染组件，也不推送远端。
